## Independence assessment

Architecture adaptation of Axiomatic Design: FR rows are outcomes; DP columns are changeable mechanisms, not merely package names. `X` is material influence, `0` is an absence justified within the stated range. An unknown is not a zero.

### Local authoring controls

Fixed declarations, references, workflow patterns, grammar, judgment-signal set, and member declarations. Board edits are permutations; chapter edits maintain valid exclusive membership; layout edits relocate whole blocks without changing discovery. Rows describe stored projections, not the availability of the whole result.

| Outcome / control | Board list | Chapter sets | Member layout | Profile | Title text |
| --- | --- | --- | --- | --- | --- |
| Story order | X | 0 | 0 | 0 | 0 |
| Group membership | 0 | X | 0 | 0 | 0 |
| Physical placement | 0 | 0 | X | 0 | 0 |
| Severity map | 0 | 0 | 0 | X | 0 |
| Stored title | 0 | 0 | 0 | 0 | X |

This local matrix is diagonal. Board projection reads no chapter or file ordering; chapters write membership only; layout cannot change content; profiles cannot mutate the IR; titles cannot rewrite identity. An external-origin edit no longer changes automation validity after removal of the translation keyword and EM011/EM012. This is a genuine removed influence.

### Whole semantic pipeline

Fixed file-discovery and HCL vocabulary contracts. Changes include declaration identity/type and workflow pattern; they are not assumed to have all dependent repairs already made.

| Outcome / mechanism | Declarations and typed namespace | Pattern grammar | Board projection | Chapter projection | Core publication |
| --- | --- | --- | --- | --- | --- |
| Unique typed binding and valid literal examples | X | 0 | 0 | 0 | 0 |
| Pattern-correct elements, edges and scenarios | X | X | 0 | 0 | 0 |
| Valid board selection and order | X | 0 | X | 0 | 0 |
| Valid chapter membership | X | 0 | 0 | X | 0 |
| Publish a complete valid model | X | X | X | X | X |

This mapping is lower triangular (decoupled), not diagonal. Renaming/removing a referenced declaration can invalidate board, chapter, edge, and scenario references. Changing a referenced type can invalidate its examples. Replacing a pattern can invalidate both elements and scenarios. Publishing only a complete valid model depends on all core branches. These influences do not disappear inside a module or a junction.

Establish declarations/binding, then check pattern, board and chapter branches, then publish. After an upstream identity/type/pattern change, recompute affected references and checks. Later projections cannot mutate declarations. Profile evaluation reads judgment signals without gating core publication.

S junctions combine projections. C junctions enforce declaration resolution before checks and core checks before publication. No automatic F iteration is required. A common parser, snapshot, memory limit or read failure can still prevent every projection; the local diagonal matrix is not fault isolation.

Full diagonality is not established while preserving typed reference integrity, pattern-specific scenarios and all-or-nothing core publication. Achieving it would require a materially different contract; no requirement was dropped or moved into a constraint during this review.

## Information Axiom

No supported joint success probabilities exist for these alternatives. There is no numerical information score. Shared parser and migration failures invalidate an assumption of probabilistic independence. Compare complete authoring/migration tasks on the same models, correctness criteria and time horizon before estimating joint success probability.

## Applied corrections

- `internal/migrate` checks the retired v0.4.0 chapter rules before rewriting.
  The normal v0.5.0 validator still accepts unordered chapters in separate files.
- Model titles carry a `TitlePresent` bit alongside the text. The bit distinguishes
  omission from `title = ""` without per-title pointer allocations. Renderer and
  interchange label selection consult it instead of treating every empty string
  as omission. Existing nonempty titles retain their text.
- Current specification and guide commands use `emhcl`, the shipped executable.
- RFC 0004 now separates its local authoring matrix from the retained semantic
  dependencies. The tool's architecture matrix includes migration instead of
  dropping FR9 from the analysis.

These corrections do not remove typed-reference checks, literal checking,
pattern-specific scenarios, or complete-model publication.

## Exercised verification

- Regression tests fail before the relevant fixes and pass afterward:
  `TestMigrationRejectsV04ChapterRanges`,
  `TestMigrationRejectsV04ChaptersInSeveralFiles`,
  `TestLiteralEmptyTitleIsDistinctFromOmission`, and
  `TestExportPreservesLiteralEmptyWorkflowTitle`.
- CLI smoke: `migrate -w` rejects the reversed chapter with exit 1 and unchanged
  input bytes. Literal empty titles export as `""`; omitted titles use IDs.
- Chromium: a generated diagram shows a blank literal title beside an untitled
  workflow labeled with its raw ID. The off-board page lists the omitted workflow
  separately. No page errors were observed.
- `make verify` completes successfully, including tests, race tests, staticcheck,
  exhaustive checks, reachable-vulnerability scanning, examples, WASM and release
  checks. The vulnerability scan reports no reachable vulnerabilities, not that
  every required module is vulnerability-free.
- All six specification models validate under `strict`.
- All twelve shipped models (six specification, six implementation) preserve
  exported content and story order against freshly built `main`. Comparisons
  normalize unordered exported collections and dependencies, but retain field,
  scenario-step and slice order. JSON export omits some native metadata, including
  chapters, so this comparison is not proof of complete native-IR equivalence.

## Verdict

The reproduced implementation defects are corrected and the exercised v0.5.0
conformance checks pass. Full-system diagonality is not satisfied under the
retained correctness requirements. Local authoring projections are uncoupled;
the semantic pipeline and migration integration are decoupled. A fully diagonal
release criterion therefore remains unmet, rather than being certified by a
renamed module boundary.
